# 奥奇传说 · 对战回放查看器（纯文字）

> 中文项目名：**奥奇传说对战回放（纯文字）**
> 仓库名用了 ASCII：`aoqi-replay-viewer`（GitHub 对纯中文仓库名的 API 校验不通过）

把《奥奇传说》的对战回放 JSON 解析成**可交互的文字战报**：拖动进度条即可逐检查点回溯整场对局，
不用录屏、不用截图，一个 HTML 文件就能把整场战斗从头看到尾。

**完全离线**：单个 HTML 文件，双击即用，不联网、不依赖服务器、不需要任何图片。

> English: a text-only replay viewer for the Chinese game *Aola (奥奇传说)*. Single offline HTML,
> no images, scrub the timeline to replay every skill cast. UI is in Chinese.

---

## 这个仓库里有什么

| 文件 | 说明 |
|---|---|
| **`aoqi-viewer.html`** | **通用版查看器**（单文件、离线）。打开后把回放 JSON 拖进去，或用右上「载入其他回放…」 |
| `aoqi_replay/viewer_template.html` | 查看器源码模板（内含全部解析与渲染逻辑，`__AOQI_EMBED_PAYLOAD__` 为数据占位符） |
| `aoqi_replay/build_viewer.py` | 把「模板 + 回放 JSON」打包成单文件 HTML（即上面的通用版再加上内嵌数据） |
| `aoqi_replay/aoqi_parser.py` | Python 参考解析器：命令行打印文字战报 / 另存结构化 timeline JSON |
| `aoqi_replay/verify_build.py` | 校验构建产物（内嵌数据完整性、脚本块是否异常膨胀） |
| `aoqi_replay/test_viewer_logic.js` | 逻辑测试：解析 / 九宫格 / 镜像 / 通灵条 / 全检查点渲染无 NaN |

> **本仓库不含任何回放样本**（回放数据涉及玩家昵称与阵容）。请用你自己的回放文件。

## 快速开始

### 只想看图：直接开查看器

1. 下载 `aoqi-viewer.html`
2. 双击打开（任何现代浏览器，Chrome / Edge / Firefox 均可）
3. 把你的回放 JSON **拖进页面**，或点右上「载入其他回放…」

拖进去的瞬间就会渲染出九宫格站位与完整文字战报。

### 想生成「打开即见战报」的单文件版

```bash
python aoqi_replay/build_viewer.py 你的回放.json 输出.html
```

### 想在命令行看战报 / 拿结构化数据

```bash
python aoqi_replay/aoqi_parser.py 你的回放.json --summary     # 只打印文字战报
python aoqi_replay/aoqi_parser.py 你的回放.json timeline.json  # 另存结构化 JSON
```

## 操作方式

| 操作 | 说明 |
|---|---|
| 拖动底部进度条 | 逐检查点回溯（核心功能） |
| `←` / `→` | 上一个 / 下一个检查点 |
| `Shift + ←/→` | 跳到上 / 下一个**轮次**起点 |
| `Ctrl + ←/→` | 跳到上 / 下一个**回合**起点 |
| `Home` / `End` | 首 / 尾 |
| 空格 | 自动播放 / 暂停 |
| `B` | 切换**站位布局**：纵向（站位左 / 战报右）⇄ 横向（双方并排 / 战报在下） |
| `L` | 把文字战报**拖出**成可拖动、可缩放的浮动窗 / 收回（`Esc` 亦可） |
| 拖分隔条 | 纵向调「站位 / 战报」左右宽度；横向调上下高度（双击重置） |
| 点战报任意条目 | 直接跳到该检查点 |

URL 参数：`?layout=h|v` 指定布局，`?detach=0|1` 指定战报是否拖出；
地址栏会跟着更新 `#ci=24` 这类锚点，复制给别人可直达该检查点。

## 检查点是怎么分的

按你的要求分三层，粒度从粗到细：

| 层级 | 对应字段 | 说明 |
|---|---|---|
| **大检查点：回合** | 回放里的 `csn` | 真正的回合号 |
| **中检查点：轮次** | 由出手方切换推算 | 双方各出手一次为一个完整来回；**一个回合包含多个轮次** |
| **小检查点：一次技能** | 每条 ACT 记录 | 普攻 / 超杀各算一个，进度条的最小单位 |

时间轴刻度：**黄线 = 回合起点**，**浅蓝线 = 轮次起点**，灰线 = 单次技能。

### 九宫格站位

回放里每个单位带 `(x, y)` 坐标，编号与屏幕位置的换算如下
（注意 `x`/`y` 与「行」/「列」是**交叉**的）：

```
格子编号 = x + 1 + 3y        屏幕行 = x + 1        屏幕列 = 3 - y
```

屏幕布局（与游戏内一致，编号 1 在右上角）：

```
第1列   第2列   第3列
 7       4       1
 8       5       2
 9       6       3
```

**横向布局下，对方（阵营1）的九宫格会左右镜像**（编号 1 落到左上角），
双方像照镜子一样正面相对；镜像只翻转列、不改行，镜像方队头会标「镜像」。

## 战报里会显示什么

- **谁出手**：施法者按阵营着色，黄框高亮，标注「普攻 / 超杀」与技能 ID
- **谁挨打**：逐条列出真正被命中的目标、血量/护盾变化、余血
- **状态**：`闪避` `格挡` `暴击` `免疫` `阵亡` `复活` `上限↑` 徽标
- **本体 / 复制体 / 附属体**：同名单位之间区分，重名单位在战报里附格子号
- **通灵条**：面板顶部显示双方通灵条（当前通灵值 / 触发阈值），
  触发通灵效果的那一帧会高亮并标出消耗量
- **每张卡三行**：`气势` / `血量` / `护盾`，各自带本检查点的变化量

### 一个关键的过滤规则

回放的 `trl` 数组会把本次「**检查过的所有单位**」都列出来（一次普攻可能列 9 个单位），
但其中只有 `isse=true` 的才真正生效。因此战报按三档处理，避免把"点名但没生效"当成伤害：

| 档位 | 判据 | 显示方式 |
|---|---|---|
| **挨打** | 闪避，或 `isse=true`，或有数值/状态变化 | 逐条列出 `血 -N` / `盾 -N` |
| **仅挂增益** | `isse=false` 且只有 `ad_bfs`/`bd_bfs` | 汇总一行「挂增益 N 个：…」 |
| **无变化** | 什么都没有 | 完全过滤 |

## 已知限制

1. **只解析第一个含记录的帧**（通常是 `br.fr[0]`）；真正多帧的战斗尚未支持。
2. **轮次**是推算的（出手方再次轮到首个出手方即断开）；**回合**直接取自 `csn`，可靠。
   若某局存在行动队列中断，轮次数可能与游戏内显示略有差异。
3. **未解码字段**：`issb`、`isor`、`ses`、`fbs` 的确切语义未确定，
   界面不展示其判断；只呈现有把握的部分。
4. **附属体判定**依据「初始气势为 0」；若某局出现气势为 0 的正常本体，可能误判（罕见）。
5. 回放协议按 `1019_1_0` 编写；其他协议版本可能不被支持。
